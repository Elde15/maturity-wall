02Data contract

What the site reads

The site is static: every model ran offline, and the browser only filters, maps and reruns the underwriting arithmetic. Each file carries its build date, data cut-off and schema version.

summary.json
Headline numbers and every chart series on the home, wall and method pages.
loans.json
The loan table, columnar, for the explorer.
uw.json
Underwriting inputs per loan at full precision, for the browser engine.
scenarios.json
Scenarios, engine parameters, market inputs and the parameter table with sources.
history/xx.json
Per-loan filing history, facts, model drivers and underwriting inputs, in 256 files keyed by the loan id's first two hex digits; read by the tear sheet.
sources.json
Every outside source, by purpose.
03Code

Rebuild it

The repository is github.com/Elde15/maturity-wall. It holds the pipeline (Python), the site (Vite and plain JavaScript), the project plan, a decision log with every departure from it, and the QA report for each of the six gates. Raw filings are not in the repository; the pipeline downloads them from EDGAR.

uv sync --extra model
uv run pytest                      # unit, golden-file, engine and site tests
uv run python -m mwall fixture     # two trusts, three snapshots: rebuild and compare with stored outputs

# full build (hours). SEC asks scripted clients to declare a contact: set your own name and email
export SEC_CONTACT="..."
uv run python -m mwall index && uv run python -m mwall discover && uv run python -m mwall filings
uv run python -m mwall download && uv run python -m mwall parse && uv run python -m mwall clean
uv run python -m mwall panel && uv run python -m mwall features --fetch
uv run python -m mwall model && uv run python -m mwall underwrite --places
uv run python -m mwall site        # writes site/public/data
cd site && npm ci && npm run build
